# خلاصه تغییرات

## Frontend (index.html + page2–5.html)
- دکمه «پیوست» کنار کادر پیام اضافه شد؛ کلیک روی آن انتخابگر فایل را باز می‌کند.
- بعد از انتخاب عکس/فایل: یک Preview (thumbnail برای عکس، آیکون+نام برای فایل) بالای کادر پیام نمایش داده می‌شود، با دکمه حذف (✕).
- اعتبارسنجی سمت Frontend: نوع فایل (JPG/PNG/WEBP برای عکس، PDF/TXT/CSV/JSON/DOCX/XLSX برای فایل) و حجم (۶MB عکس، ۸MB فایل) قبل از ارسال بررسی می‌شود و خطای واضح نشان داده می‌شود.
- هنگام ارسال پیام همراه با پیوست، به‌جای مسیر تصمیم‌گیری/جست‌وجوی معمول، مستقیماً یک درخواست `multipart/form-data` به همان Worker فعلی ارسال می‌شود (فقط یک درخواست AI مصرف می‌شود).
- پیام‌های حاوی عکس/فایل هم در حباب پیام کاربر (thumbnail یا چیپ فایل) و هم در localStorage ذخیره می‌شوند.
- ظاهر و رفتار قبلی سایت (چت، تاریخچه گفتگوها، جستجو، حالت صوتی، احراز هویت، تم روشن/تاریک) دست‌نخورده باقی مانده است.
- همین تغییرات عیناً روی هر ۵ صفحه (index.html و page2–5.html) اعمال شده چون موتور چت مشترک است.

## Backend (worker.js)
- Binding های `env.AI` و `env.SESSIONS` و محدودیت ۱۰ درخواست/ساعت دقیقاً مثل قبل حفظ شده‌اند.
- مسیر JSON فعلی (`POST` با `Content-Type: application/json`) بدون هیچ تغییری کار می‌کند — کاملاً بک‌ورد-کامپتیبل.
- یک مسیر موازی جدید اضافه شده: اگر `Content-Type` درخواست `multipart/form-data` باشد، به تابع جدید `handleMultipart` هدایت می‌شود.
  - فیلد `image`: اعتبارسنجی نوع/حجم → به مدل Vision (`@cf/meta/llama-3.2-11b-vision-instruct`) ارسال می‌شود، چون `TEXT_MODEL` فعلی (`llama-3.2-3b-instruct`) قابلیت Vision ندارد. این مدل واقعاً در Workers AI موجود است (بررسی شد).
  - فیلد `file`: اعتبارسنجی نوع/حجم → استخراج متن با پارسرهای سبک داخلی (بدون هیچ کتابخانه خارجی، چون Worker شما بدون مرحله Build است) → متن استخراج‌شده همراه پیام کاربر به `TEXT_MODEL`/`CODE_MODEL` داده می‌شود.
  - پاسخ‌ها دقیقاً با ساختار خواسته‌شده در `type: "text" | "image" | "file"` برگردانده می‌شوند.
  - در صورت نامعتبر بودن نوع فایل، حجم بیش از حد، یا عدم توفیق در استخراج متن، پیام خطای فارسی واضح با کد HTTP مناسب (415/413/422) برگردانده می‌شود.

### استخراج متن از فایل‌ها (پیاده‌سازی داخلی، بدون کتابخانه)
- **TXT / JSON / CSV**: مستقیم decode می‌شوند.
- **DOCX / XLSX**: چون این فرمت‌ها خودشان یک فایل ZIP هستند، یک ZIP-reader کوچک و خالص-JS نوشته شده که `word/document.xml` یا شیت‌های Excel را می‌خواند. **تست شد و درست کار می‌کند** (از جمله متن فارسی).
- **PDF**: یک استخراج‌کننده best-effort نوشته شده که استریم‌های محتوا را می‌خواند، هم متن‌های ساده و هم فونت‌های embedded (از طریق ToUnicode CMap) را پشتیبانی می‌کند، و برای متن فارسی/عربی اصلاح جهت (bidi) انجام می‌دهد. **تست شد و کار می‌کند.**
  - محدودیت شناخته‌شده و ذاتیِ این روش (بدون کتابخانه کامل PDF): برای PDFهای اسکن‌شده (تصویر)، رمزگذاری‌شده، یا با فیلترهای فشرده‌سازی غیرمعمول، ممکن است متن استخراج نشود؛ در این حالت طبق خواسته شما، به‌جای خرابی، پیام خطای واضح «متنی از این فایل استخراج نشد» به کاربر نمایش داده می‌شود.

## نحوه Deploy
1. محتوای `worker.js` را در Cloudflare Worker فعلی (Danyal AI) جایگزین کنید و Deploy بزنید. Bindingهای `AI` و `SESSIONS` و متغیر `TINYFISH_API_KEY` را دست نزنید.
2. فایل‌های `index.html`, `page2.html` تا `page5.html`, و `sw.js` را جایگزین نسخه‌های فعلی روی سایت کنید (بقیه فایل‌ها مثل آیکون‌ها و manifest تغییری نکرده‌اند).
3. چون Service Worker نسخه کش را بالا برده (v2 → v3)، کاربران بعد از رفرش صفحه، نسخه جدید HTML را می‌گیرند.

## نکته امنیتی
هیچ API Key در Frontend قرار نگرفته؛ همه پردازش فایل/عکس در Worker انجام می‌شود و فایل‌ها فقط در حافظه (در طول همان درخواست) پردازش می‌شوند و جایی ذخیره دائمی نمی‌شوند.
